# 巡检与蒸馏

规则（怎么计数、何时提议、格式）只在库根目录 `CLAUDE.md`；本 skill 只讲顺序。开工前先读 CLAUDE.md 的铁律、3.3、4.1、第五节、6.5、6.6、6.10、6.11。

## 1. 什么时候
- **每周一次**（定时任务），用户说「巡检」「蒸馏一下」时随时做。
- **增量**：只处理上次巡检之后新增或更新的 B 层文件和 A 层进展日志新条目。上次日期看 [[个人数据库]] 进展日志里最近一条「巡检」；没有就做全量。
- **每月第一次巡检**另外重写画像（第 4 节第 6 步）；**1、4、7、10 月的第一次巡检**另外写上一季回忆录（第 4 节第 5 步）。

## 2. 蒸馏的原料
- strategy ← 只用 CLAUDE.md 6.10 认可的出处（用户亲历的事）。
- situation 综述 ← 该情境下的 insight + strategy。
- knowledge ← B-Topics + B-Tools + B-Insights + C-Strategies。
- memoir ← 见 CLAUDE.md 6.5 的原料一条。

## 3. memoir 和 knowledge
- 写法只在 CLAUDE.md 6.5、6.6。
- 新 knowledge 体系：某一大类原料多了，或用户反复跨文件问同一主题时，按 CLAUDE.md 3.3 提议。

## 4. 巡检步骤
1. **找新原料**：按第 1 节的增量范围，看 B-Emotions、B-Insights、B-Dialogues、B-Topics、B-Tools 和 A 层进展日志。
2. **找没被引用的**：新原料里还没被任何 C 文件的 **证据** / **反例** 栏引用的。
3. **归入已有 C 文件**：追加进它的 **证据** 栏，更新结论，改 `updated`；改过证据栏的 strategy 按 CLAUDE.md 6.10 重算等级。
4. **提议新建**：够不够提议，按 CLAUDE.md 3.3；只提议，用户同意再建。
5. **季度回忆录**：1、4、7、10 月的第一次巡检，按 CLAUDE.md 6.5 写上一季。
6. **重写画像**：每月第一次巡检，按 CLAUDE.md 6.11 重写 `C-WhoRU.md` 的 `## 画像`；原料是上月新增的 B 层记录、A 层进展日志、旧画像和各策略等级。
7. **顺带查格式**：frontmatter 取值、目录与 type、done 未归档、新文件的断链。能撤回的直接修，修了什么记进日志；原话一律不动。

## 5. 产出
- 在 [[个人数据库]] 进展日志追加 `### YYYY-MM-DD · 巡检`，只列事实：处理了哪些原料、改了哪些 C 文件、提议了什么、画像改了哪几条、哪些等级变了、查出和修了哪些格式问题。
- 要用户决定的放进 `0-Unclear/`（CLAUDE.md 6.7）或在对话里逐条列出，由用户定。
- 没有新原料时，日志只记一行「无新原料」。
- 向用户报告按 CLAUDE.md 对话原则，用大白话。
