# 入库

规则（放哪、长什么样、不许做什么）只在库根目录 `CLAUDE.md`；本 skill 只讲顺序。不问用户要不要存，做完再报告。

## 1. 先读
- `CLAUDE.md` 的铁律、第三节、第五节、第七节。
- `C-WhoRU.md` 的「近况」：知道用户在忙什么，才知道一句话该挂在哪个项目下。

## 2. 判断输入性质
先问「这是什么」，再问「放哪」。一条输入可以拆成几份。

| 它是 | 归处（以 CLAUDE.md 为准） |
|---|---|
| 用户自己的感受 | emotion，三节都用原话，没说感悟就留空 |
| 冒出来或看到的想法，关于自己 | insight |
| 学到的外部知识 | topic |
| 某件事的进展、决定、待办、deadline | 已有 project / holiday 追加；是新的事就新建 project |
| 没有归属的小事 | [[日常事务]] 的待办 |
| 想去的地方、旅行计划 | holiday |
| 自己做的工具、程序 | B-Tools 项目的 README / CHANGELOG |
| 和 AI 深谈后有了结论 | dialogue |
| 个人资料放在哪 | info；证件号、密码等只记在哪，不记原文 |
| 一餐饭的照片或描述 | meal |
| 链接、截图、文章、视频 | 先读内容，再按上面判断；视频先转成文字 |
| 纠正已有记录里的事实 | 原文不改，在原记录后追加一行带日期的更正 |
| 说某条策略「没用」、侧写「不对」 | 先按上面入库，再留给下次巡检重算 |
| 要求以后换一种做法 | 不入库，是改规则：问用户要不要写进 CLAUDE.md |
| 工作文档、只服务眼下的安排、噪音 | 不入库（3.1） |
| 判断不了 | `0-Unclear/` 选择题（6.7），标出推荐项 |

## 3. 找归处
1. **追加优先**：先按文件名和 frontmatter 搜；是已有文件的后续就追加，带日期。
2. **新建**：确实是新东西，按第五节的 frontmatter 和正文结构写，取值只用第七节。
3. 别的 Agent 负责的文件不碰，把内容转给负责它的那位。

## 4. 写
- 原话放「」，逐字，不改错字、不拼接、不润色；AI 补的背景另起一行，标「（AI 补充）」。
- 只追加、新建、归档；要移动或改名，按铁律 8 同步改链接。
- 改了文件就改 `updated`（emotion、insight 除外）。

## 5. 读回核对
重读刚改的文件：原话一字不差；type 与目录相符；字段齐全、取值在表内；有 `## 关联链接`；新链接都指向真实文件（虚拟概念除外）。

## 6. 报告
- 一句话说放在哪，附文件链接；没记的说没记什么、为什么。
- 放进 Unclear 的，只问一个问题，选项一行一个。
- 用户在说难受的事时，报告压到最短，或等他说完再提。
- Inbox 处理完清空。
