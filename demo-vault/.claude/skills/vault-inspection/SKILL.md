# 巡检与蒸馏

规则以库根目录 `CLAUDE.md` 为准；本 skill 讲蒸馏和巡检的做法。开工前先读 CLAUDE.md 的铁律、4.1、第五节、6.10、6.11。

## 1. 什么时候
- **每周一次**（定时任务），用户说「巡检」「蒸馏一下」时随时做。
- **增量**：只处理上次巡检之后新增或更新的 B 层文件和 A 层进展日志新条目。上次日期看 [[个人数据库]] 进展日志里最近一条「巡检」；没有就做全量。
- **每月第一次巡检**另外重写画像（第 5 节第 6 步）；**1、4、7、10 月的第一次巡检**另外写上一季回忆录（第 4 节）。

## 2. 蒸馏的原料
- strategy ← B-Emotions + B-Insights + B-Dialogues（复盘类优先）+ A 层进展日志里用户亲历的事。
- situation 综述 ← 该情境下的 insight + strategy。
- knowledge ← B-Topics + B-Tools + B-Insights + C-Strategies。
- memoir ← 见第 4 节。

## 3. strategy 怎么计数
等级区格式和四档见 CLAUDE.md 6.10。
- **只算第一手现场**：用户亲历并记下的事，出处只能是 B-Emotions、B-Insights、B-Dialogues（复盘类，只算用户本人的经历）或 A 层进展日志。AI 的分析、别人的经验、书和理论不算，写进 **来源** / **理论依据**。
  - 同一件事有多条记录，算 1 次。
  - 一件事只进一栏：照步骤做了算「执行」；没做、只是模式出现了算「出现」。
- **出现**：识别信号里的模式在现场出现了。只说明问题存在，不抬高等级。
- **执行**：照破解步骤（至少一步）做了，当时有没有想到这条策略都算。每次标一个结果：**有效**（符合预期）、**无效**（没用或适得其反）、**未记录**（看不出结果）。
- **反例**：模式出现了，但机制解释不通。记进 **反例** 栏，计算时按无效算。
- **证据栏**：等级区里的每个链接，在 `## 关联链接` 的 **证据**（或 **反例**）栏都要有一行：`- [[原记录]]（YYYY-MM-DD）—— 一句话说明`。「仍缺什么」和「证据集中度」说明照旧保留，不计次数。
- 用户说某条策略「不对」「没用」：先入库这句话，再记一次无效。
- 重算后改 `updated`。

## 4. memoir 和 knowledge 的写法

**memoir**（一季一份）
- 原料：A-Projects 进展日志、A-Archive（本季结束的）、A-Holidays、B-Emotions、B-Insights、B-Topics（本季 updated）、B-Tools（本季 CHANGELOG）、B-Dialogues；不含 B-Info、B-Meals。
- 正文：季度综述（本季主线 + 各项之间的潜在联系）→ 时间正序时间线：
  `- YYYY-MM-DD 🟢/✈️/❤️/💡/📚/🛠️/💬 [[原文件]] 一句概述`
  （🟢 项目 · ✈️ 旅行 · ❤️ emotion · 💡 insight · 📚 topic · 🛠️ tool · 💬 dialogue）

**knowledge**（一份 = 一个知识体系）
- 分工：B-Topics 是原料；C-Knowledge 把原料总领起来、理出关系；C-Strategies 讲「遇到某种情形怎么做」。
- `## 总领`：3–5 句说清全貌与主线，结论前置。
- `## 知识地图`：按逻辑层级（不按文件）列出所含 topic / tool / insight / strategy。
- `## 关系`：每条 `[[A]] → [[B]]：关系类型 + 一句说明`，类型取 因果 / 依赖 / 对比 / 包含 / 矛盾。
- `## 缺口`：没弄懂的、原料之间矛盾的。
- `## 关联链接`：**证据** 栏列出用到的原料。
- 某一大类原料多了，或用户反复跨文件问同一主题时，先提议，同意后再生成；原料更新后可整份重跑。

## 5. 巡检步骤
1. **找新原料**：created / updated 晚于上次巡检的 B-Emotions、B-Insights、B-Dialogues、B-Topics、B-Tools 文件，加上 A 层进展日志的新条目。
2. **找没被引用的**：新原料里还没被任何 C 文件的 **证据** / **反例** 栏引用的。
3. **归入已有 C 文件**：追加进它的 **证据** 栏，更新结论，改 `updated`；改过证据栏的 strategy 按第 3 节重算。
4. **提议新建**：同一情境下有 3 条以上没被引用、指向同一模式的原料时，提议新建 strategy；新情境、新 knowledge 体系一律先提议。
5. **季度回忆录**：1、4、7、10 月的第一次巡检，按第 4 节写上一季。
6. **重写画像**：每月第一次巡检，按 CLAUDE.md 6.11 重写 `C-WhoRU.md` 的 `## 画像`；原料是上月新增的 B 层记录、A 层进展日志、旧画像和各策略等级。
7. **顺带查格式**：只查不改原文。frontmatter 取值、目录与 type、done 未归档、新文件的断链。

## 6. 产出
- 在 [[个人数据库]] 进展日志追加 `### YYYY-MM-DD · 巡检`，只列事实：处理了哪些原料、改了哪些 C 文件、提议了什么、画像改了哪几条、哪些等级变了、格式问题。
- 要用户决定的放进 `0-Unclear/`（CLAUDE.md 6.7）或在对话里逐条列出，不自己定。
- 没有新原料时，日志只记一行「无新原料」。
- 向用户报告用大白话：先总结，再细节，最后逐条列要他决定的事。
