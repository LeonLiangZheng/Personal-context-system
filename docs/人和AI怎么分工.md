# 人和 AI 怎么分工

## 先说清楚：哪些是平台的，哪些是这套系统设计的

| 平台提供的（不是本项目做的） | 本项目设计的 |
|---|---|
| 多个 Agent 同时运行、互相传话、定时触发 | 一份所有 Agent 都遵守的规则文件 `CLAUDE.md` |
| 读写电脑上的文件夹 | 库的信息架构：执行 / 记录 / 蒸馏三层、字段取值表 |
| 在手机上和 Agent 对话 | 每个 Agent 负责什么、哪些文件归谁写 |
| 模型本身的理解和写作能力 | 证据分级、原话与 AI 判断分开、用户侧写这些约束 |
| | 看板（`cockpit-web/`，在 AI 协助下写成） |

作者用的是 Claude 的项目功能加桌面端的文件夹授权；同一份规则也给 Obsidian 里的 Claude 插件和读 `AGENTS.md` 的 Codex 用过。换平台时，要换的是上面左栏，右栏不变。

## 分工

```text
                  用户（手机上说一句话）
                          │
                   协调 Agent：判断这句话该交给谁
        ┌─────────────┬───────┴───────┬──────────────┐
   日常入库          规则与巡检       每日晨报         电脑端移动改名
   写 A、B 层        改规则文件       08:00 定时       通过 Obsidian 执行，
   按规则归类        每月 1 日巡检    只改侧写「近况」   保证链接不断
                     重写侧写「画像」
```

- **一句话入库**：在任何对话里提到的信息，协调 Agent 转给「日常入库」，由它按规则判断放哪、怎么写，不再逐条问用户「要不要存」。拿不准的放 `0-Unclear/` 等用户勾选。
- **规则只有一个负责人**：只有「规则与巡检」能改 `CLAUDE.md`，改完同步 `AGENTS.md`，并通知其他 Agent。用户随时可以提新规则，由它写成条文。
- **定时任务**：每天 08:00 的晨报读库后给出当天的提醒，并重写侧写的「近况」；每月 1 日的巡检把新素材归进已有经验、重算证据等级、重写画像，并在 `[[个人数据库]]` 的进展日志里留一条记录。
- **移动和改名**：只能在 Obsidian 里做（命令行或插件接口），因为 Obsidian 会同时改掉所有指向它的链接；用普通的文件移动会让链接全断。删除只进回收站。
- **专项任务自己写自己的文件**：比如某个实验项目、简历素材，由负责那件事的 Agent 写自己的文件，日常入库不去碰它，避免两个 Agent 改同一个文件。

## 踩过的坑

- **两个 Agent 改同一个文件**：同步延迟会把旧版本送回来，覆盖掉新的修改。现在的做法是每个文件只有一个负责人，改之前先重读，改完过一会儿再读一遍确认。
- **Agent 之间传话会走样**：协调 Agent 转达用户的话时，附上用户原话的链接，不只转述。
- **AI 默认会问「要不要存」**：问多了用户就烦，最后什么都不记。规则里写明由 AI 自己判断、做完再报告。
