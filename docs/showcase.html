特点一 · 上下文归你

换一个 AI，读一页就能接上

AI 产品自带的记忆属于平台，看不到，也带不走。这里的上下文全是你库里的 Markdown 文件：规则写在 CLAUDE.md（AGENTS.md 是同一份），关于你的要点汇总在一页 C-侧写.md。

Claude、Codex 或 Obsidian 里的 AI 插件，打开库先读这两份，就知道你是谁、在忙什么、要注意什么，再按标签只调这次需要的几篇原记录。

来历：接力文档作者最早的做法，是每和 AI 干完一段活，就让它写一份交接文档：做到哪了、排除过什么、踩过什么坑、我习惯怎么做。下一个 AI 读完接着干，不管是在网页、编辑器还是桌面端。后来这些交接文档合成了一份规则和一页侧写。
侧写是索引，不是证据每条都带出处。别的文件要引用事实，得回到原记录，不能引用侧写。

特点二 · 经历长成手册

你经历过的事，长成自己的应对手册

难受了、卡住了、想通了，随手记一条：发生了什么，当时怎么想，事后一句感悟。AI 把记录归进你定的几个情境；同一种模式出现几次，就提炼成一条策略：什么信号说明它又来了，为什么会这样，下次怎么做。

策略里的识别信号直接引用你当时的话，每条策略都能追溯到具体事件。之后照着做了，有用没用都记回来。

和书上的方法论有什么不同书上的道理写给所有人。这里每条策略都从你自己的记录里长出来，也会被你自己的经历推翻。书和 AI 给的建议只记作来源，不算数。
每一步都能往回追
  • 「…」你的原话，一个字不改，点开就是当时那条记录。
  • （AI 判断）AI 的推测，比如“为什么会这样”，单独标出，可以推翻。
  • “这条不对”你说一句，就记成一次没用，策略跟着改等级。

特点三 · 你只管说

你只管说，整理是 AI 的活

想到什么就说一句，在手机上也行，或者往收件箱里丢一行字。放到哪、怎么写、什么时候提炼，由几个 AI Agent 按同一份规则分工去做，做完告诉你结果。

你只做三件事：说话、勾选择题、定规则。归类、提炼、维护都不用你动手。

为什么不先问一句“要不要存”AI 默认会问。问多了人就烦，最后什么都不记。所以规则写明：AI 自己判断，做完再报告；只有真拿不准的，才出一道选择题。

怎么做到的

三层结构，一份规则

分层只看一个问题：这个文件删了，AI 能不能重新造出来？造不出来的是你的第一手记录，一个字都不改；造得出来的是 AI 的提炼，随时可以删了重跑。

A执行

项目、旅行。有状态，会结束；结束了归档，不删。

A-Projects/ · A-Holidays/ · A-Archive/

结束后归档，原文不改

B记录

情绪、想法、和 AI 的对话、学习笔记。第一手素材，原话一字不改。

B-Emotions/ · B-Insights/ · B-Dialogues/ · B-Topics/ · B-Tools/ · B-Info/

删了谁也造不回来

C蒸馏

AI 从 B 层提炼出的情境、策略、知识综述、季度回忆录和侧写。每句都指回 B 层的出处。

C-Playbook/ · C-Knowledge/ · C-Memoirs/ · C-侧写.md

删了可以按规则重跑

这个项目设计的

  • 一份所有 AI 都遵守的规则：CLAUDE.md，AGENTS.md 是原样副本
  • 三层结构和字段取值表
  • 从记录到情境再到策略的提炼流程，策略带证据和反例
  • 多个 Agent 各管一摊：日常入库、规则与巡检、每日晨报、移动改名
  • 看板：一个网页文件，直接读库，按规则做 11 项体检

用的是平台现成的

  • 多个 Agent 同时运行、互相传话、定时触发
  • 读写电脑上的文件夹，在手机上对话
  • 模型本身的理解和写作能力

换平台时只换这一栏，项目设计的那部分不变。

五分钟试一下

打开 GitHub 仓库

  2. 让你的 AI 在 demo-vault/ 里工作，说“整理收件箱”，和上面特点三的例子对照；或者问“我最近在忙什么”。
  3. 用 Edge 或 Chrome 打开 cockpit-web/index.html，选 demo-vault/ 文件夹，看看看板和体检结果。
  4. 想用在自己的库上，把 rules/CLAUDE.md 和 AGENTS.md 复制到库根目录，改掉里面的取值表。
