# 版本演进

这套规则不是一次设计出来的，是作者在自己的库上用了三个多月、改了四次大版本长出来的。每一版都是真实使用中先撞到问题，再改规则。下面每版按「问题 → 改动 → 验证 → 教训」写。

> 作者自己的库不公开。这里只写结构和规则的变化，不写库里的个人内容。V1 之前的两个阶段没有改动记录，是从文件痕迹推断的。

```text
Notion 表格 ──► 本地 Obsidian ──► V1 引入 AI ──► V2 目录语义 ──► V3 三层重构 ──► V4 多 Agent
（人工）         （人工）          原料 / 结论分开   跨设备          执行 / 记录 / 蒸馏   手机即入库
```

## 起点：人工维护（2025 ~ 2026-07）

- 最早是 Notion 在线表格，只记项目；2026-04 下载到本地，用 Obsidian 管理，项目一个文件、任务一个文件，全靠手写。
- 同在 2026-04，作者开始在每段 AI 协作结束时让 AI 写一份「接力文档」：做到哪了、排除过什么、踩过什么坑、下一个 AI 从哪接、自己习惯怎么做，在网页、编辑器、桌面端的 AI 之间带着走。这是后来 `CLAUDE.md` 和用户侧写的前身。
- 问题：129 个任务文件碎在各处；手写的 35 条「人生结论」和原始素材混在一起，分不清哪些是事实、哪些是当时的看法。

## V1 · 引入 AI 共建（2026-07-06）

- **改动**：129 个任务按所属项目合进 24 个项目文件，18 个死项目归档。35 条手写结论**降级为原料**，由 AI 跨文件提炼出「应对策略」，每条必须附证据链接。规则第一次写进 `CLAUDE.md`。
- **验证**：第一个自动化流程「整理收件箱」跑通。
- **教训**：结论不能直接写，要从原料长出来，并且能指回原料。这是后来「证据分级」的起点。

## V1.1 · 第一次真实问库（2026-07-21）

- **问题**：用「我有哪些没意识到的问题」去问库，AI 给出 4 条盲点假说，被作者逐条反驳：应该先读提炼过的结论；单条记录会把画像拉偏；素材有时效；情绪记录会是最少的一层。
- **改动**：定出判断标准——**「删了 AI 能不能重新造出来？」** 能重造的是蒸馏层，不能的是原始层，原始层一个字都不能改。
- **教训**：AI 很会从一两条记录里编出一个完整的故事。要防的不是 AI 不聪明，而是它太快下结论。

## V1.2 · 规范审计与看板（2026-08-17）

- **问题**：对照规则扫全库，发现 12 处「规则漂移」：AI 写着写着就自创了没登记的类型和字段。
- **改动**：确立分工——**机械统计归看板，价值判断归对话**（后来的铁律 6「判断不落盘」）。
- **教训**：规则写了不等于被执行，要有能机械检查的地方。

## V2 · 目录语义与跨设备（2026-08-24）

- **改动**：目录前缀定下语义；写出换电脑也能跑的部署方案（笔记随同步走，运行环境每台机器重建）。
- **踩坑**：第一次遇到「多个 AI 同时写」：同步延迟把旧路径的文件送回来，已经废弃的目录又「复活」了。
- **教训**：大改结构的当天必须再巡检一次；全库替换时要排除历史日志。

## V2.1 · 网页驾驶舱（2026-09-24）

- **问题**：发现看板依赖的 Obsidian 插件从来没装过，一个多月里看板的查询一条都没生效，而 AI 和人都没发现。
- **改动**：当天做出单文件网页版驾驶舱（本仓库的 `cockpit-web/`），零安装、只读，另加库体检。
- **教训**：「以为在运行」最危险。能跑起来的检查比写在规则里的检查可靠。

## V3 · 执行 / 记录 / 蒸馏三层重构（2026-09-29）

- **改动**：手绘草图 → 结构框图 → 新规则文件，335 行精简到约 220 行，只写规则不写历史。按信息流向重排为三层：**A 执行（有状态、会结束）· B 记录（第一手素材）· C 蒸馏（AI 合成、可重跑）**。字段取值集中成一张表。
- **验证**：迁移前整库备份；迁移后 237 个文件逐个校验，**0 处不合规**，新产生的断链 2 处。随后做了第一次全库蒸馏。
- **教训**：分类按「信息从哪来、往哪去」比按「内容是什么」稳定。

## V4 · 多 Agent 协作，手机即入库（2026-10-09 起）

- **改动**：在 Claude 的项目里搭一个协调 Agent 加多个线程 Agent，各管一摊：日常入库、规则与巡检、每日 08:00 晨报、电脑端的移动改名。手机上说一句话就能入库。
- **10-14**：加入「经验证据分级」「原话与 AI 判断分开」「用户侧写」三条规则（见 `docs/设计原则.md`），13 条经验全部按新规则重新分档；看板跟着加了对应的一栏。同一天通读全库后，对外讲的三个特点定为「上下文归你」「经历长成自己的应对手册」「你只管说」；证据分级和原话标注归进第二个特点，作为手册的质量保证，不单独当卖点。
- **10-16**：发现「验证次数」里混进了「问题又出现了」，不全是「照着做有用」，次数虚高。拆成「出现次数」和「执行次数」，每次都链接到具体记录，只有照着做并且有效才抬高等级。13 条经验重算后，原来标「已验证」的一条都不剩；看板跟着改成能核对次数和链接数。
- **教训**：多个 Agent 一起干活时，最容易出事的是两个 Agent 改同一个文件。每个文件只认一个负责人。Agent 的调度是平台提供的，这套系统设计的是规则和分工，见 `docs/人和AI怎么分工.md`。
